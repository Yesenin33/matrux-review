# TASK-R-C — онбординг на старте и после обновления, вход через ВК обязателен

Проект: `/root/palma`. Задача выполняется после `TASK-R-A.md` и `TASK-R-B.md`. Модель: claude-opus-5-5.

## 1. Порядок запуска приложения

Холодный старт приложения:

1. если онбординг ещё не показывался на этой версии — полноэкранные слайды (`OnboardingScreen.kt`, уже существует);
2. после последнего слайда — экран входа через ВК (`SignInOverlay` / `SignInScreen.kt`, вход через существующий `graph.signIn`);
3. только после успешной авторизации открывается приложение (вкладки Главная/Каталог/Знания/Подписка).

Если пользователь уже авторизован, но версия приложения изменилась — показать слайды один раз, затем сразу приложение, без повторного входа.

## 2. Когда показывать слайды

- **Первый запуск** — слайдов ещё не было.
- **После обновления приложения** — сохранять `versionCode` (`BuildConfig.VERSION_CODE`), на котором слайды показаны; если текущий `versionCode` больше сохранённого — показать слайды один раз и записать новый.
- хранить в `LocalState` (`app/src/main/java/ru/palma/app/data/LocalState.kt`): заменить/дополнить флаг `onboarded` на `onboardVersion: Int`; ленивое чтение и запись — как у остальных полей этого класса.
- `Onboarding` (`app/src/main/java/ru/palma/app/account/Onboarding.kt`) сейчас показывает слайды по условию `signedIn && !done`. Условие изменить: слайды показываются **до** входа, независимо от `signedIn`, по признаку версии.
- метод `replay()` и связанный с ним вызов из экрана подписки удалены ещё в задаче R-A — если остались хвосты, убрать.

## 3. Вход через ВК обязателен

Файл `app/src/main/java/ru/palma/app/MainActivity.kt`: `gateOpen` (`graph.gate.open`), `BackHandler(enabled = gateOpen) { graph.gate.dismiss() }`, `SignInOverlay(visible = gateOpen, …)`.

Требуется:
- пока пользователь не авторизован, приложение показывает **только** слайды/экран входа. Вкладки и любые экраны не отрисовываются, нижнее меню недоступно.
- экран входа **нельзя закрыть**: убрать `BackHandler`-dismiss, закрытие по тапу вне окна, свайп, любую кнопку «позже»/«пропустить». Кнопка «назад» на телефоне на экране входа не выводит из приложения в рабочее состояние — допустимо только сворачивание активности системой.
- авторизация отозвана/истекла (`AuthNotConnected`, отзыв ключа устройства) — приложение возвращается на экран входа, а не в рабочую часть.
- никаких текстов, объясняющих, что нужно войти: только сам экран входа.

## 4. Тесты

- тест на порядок запуска: без онбординга — слайды, затем вход; после онбординга и входа — сразу главная; при смене `versionCode` — слайды один раз.
- тест на обязательность входа: без авторизации вкладки недоступны, dismiss экрана входа невозможен.
- снимки стенда: `07-gate-*` (экран входа) пересоздать, если разметка изменилась; добавить снимок слайдов, если его нет.

## Границы

- Не трогать `dist/`, `art/`, `stand/`, `image-build/*rootfs`, `backend/data/images`.
- Ни одной русской строки в Kotlin — только `strings.xml`; никаких подсказок в интерфейсе.
- Вход через ВК — существующая реализация (`VkAuth`/`graph.signIn`), сторонние SDK не добавлять.
- Gradle — по одной задаче: `./gradlew assembleDebug`, затем тесты.

## Сдача

1. `./gradlew assembleDebug` — зелёная сборка.
2. Тесты порядка запуска и обязательного входа, обновлённые снимки.
3. Отчёт: «доказано командой + вывод» / «не проверено», правленые файлы, что стало с `LocalState.onboarded`, как проверялся запуск после обновления.
