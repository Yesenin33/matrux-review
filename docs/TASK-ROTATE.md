# Задача: поворот экрана без пересборки рабочего стола

Проект: /root/palma. Гость — Linux в proot, X запускает `/root/palma/image-build/palma-session`.
Сейчас поворот = `apply_geometry` → убить Xvfb/Xvnc и xfce4-session → поднять заново. Все программы
пользователя гибнут, экран чёрный 10–30 с.

## Что сделать

Новый файл `/root/palma/image-build/palma-session.next` — копия текущего `palma-session` с переделкой:

1. X-сервер поднимается один раз на **максимальный квадрат**: `SIDE = max(W, H)` из аргумента GEOMETRY,
   экран `SIDExSIDE`. Стол XFCE стартует один раз и больше не перезапускается при повороте.
2. Поворот применяется через `xrandr --fb WxH` (без перезапуска X и без `kill_desktop`). Если `xrandr`
   отказывается менять размер — оставить текущий путь с пересборкой как fallback, но логировать это в
   `/tmp/trace.log` строкой `geometry fallback rebuild`.
3. После смены размера: подогнать рабочий стол XFCE под новый размер (панель на всю ширину, без
   перезапуска сессии) и выставить `xfwm4` рабочую область.
4. `geometry-request` остаётся: файл читается, применяется, удаляется. Только теперь он меняет размер
   через xrandr, а не пересобирает.
5. Сохранить всё остальное поведение: `-localhost`, отсутствие `-xd`, Xvnc при наличии, fallback на
   Xvfb+x11vnc, `RESTARTS`, русский язык, отсутствие пояснительных комментариев в коде.

## Проверка перед сдачей

- `sh -n palma-session.next` — синтаксис.
- В chroot `image-build/debian13-rootfs` (там есть `xrandr` и `xwininfo`) поднять `Xvfb :9` на 2048x2048,
  применить `xrandr --fb 900x2000` и `xrandr --fb 2000x900` — доказать, что размер меняется без
  перезапуска сервера. Учесть: у Xvfb нет RandR-выхода на весь экран, поэтому смена `--fb` требует,
  чтобы новый размер был **не больше** экрана; если не работает — прямо написать это в отчёте и
  оставить fallback.
