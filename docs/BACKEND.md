# Бэкенд Palma — задание

Стек: Python 3.12, FastAPI, SQLite, uvicorn, pytest, ruff. Без Docker, без Postgres.
Каталог: `backend/`. Всё запускается одной командой, описанной в `backend/README.md`.

## Что отдаёт сервер

1. `GET /api/health` → `{"ok": true}`.
2. `GET /api/manifest` → каталог образов и паков:
   `{"version": int, "generated_at": iso, "images": [{"id", "name", "distro", "desktop",
   "size_bytes", "sha256", "min_ram_mb", "pro": bool, "url"}]}`.
   Заголовки `ETag` и `Cache-Control: public, max-age=60`; при совпадении `If-None-Match` → `304`.
3. `GET /api/images/{id}` → файл образа, потоком.
   - `Accept-Ranges: bytes`, поддержка `Range` → ответ `206` с `Content-Range`.
   - Докачка обязательна: обрыв на 200-м мегабайте не должен ломать загрузку.
   - `ETag` = sha256 файла; `Content-Length` точный.
   - Неизвестный id → `404`, файла нет на диске → `503` с понятным телом.
4. `POST /api/devices/register` → тело `{"device_id": "<client-generated>", "name": str|null}`,
   ответ `201 {"device_id", "device_key", "tier", "expires_at"}`. `device_key` — 32 случайных байта
   в base64url, на сервере хранится только sha256, показывается один раз. Повторная регистрация
   того же `device_id` без верного ключа → `409 device_exists`, с верным ключом → `200` без `device_key`.
   Маршруты `sub/status`, `sub/verify` и `home/{device_id}` требуют заголовок `X-Device-Key`.
   Нет ключа, ключ неверный или от другого устройства → `403 forbidden`, никогда не `404` и не `500`.
5. `GET /api/sub/status?device_id=...` → `{"tier": "free|pro|lifetime", "expires_at": iso|null, "checked_at": iso}`.
6. `POST /api/sub/verify` → тело `{"purchase_id", "product_id", "device_id"}`.
   Проверка покупки в RuStore API, режим заглушки через env `RUSTORE_STUB=1`:
   - `purchase_id`, начинающийся на `ok` → `ACTIVE`;
   - на `pause` → `PAUSED` (доступ сохраняется до конца оплаченного периода);
   - на `stop` → `TERMINATED` (доступ прекращается, уже установленное окружение работает);
   - иначе → `404` и тело `{"error": "purchase_not_found"}`.
   Одна покупка не может быть привязана к двум устройствам: повторная привязка к другому
   `device_id` → `409`.
7. `POST /api/home/{device_id}` + `GET /api/home/{device_id}` → облачный бэкап домашней папки.
   `POST` принимает multipart-архив, кладёт по sha256, возвращает размер и дату.
   `GET` отдаёт последний архив потоком с поддержкой `Range`.
8. Админские маршруты под заголовком `X-Admin-Token` из env `PALMA_ADMIN_TOKEN`:
   - `POST /api/admin/images` — публикация образа (метаданные + файл), `409` на дубликат sha256;
   - `GET /api/admin/images` — список;
   - `DELETE /api/admin/images/{id}` — снять с выдачи, файл оставить;
   - `GET /api/admin/subscribers` — сводка: всего, pro, lifetime, истекают за 7 дней.
   Нет заголовка или он неверный → `403`, никогда не `500`.

## Обязательные свойства

- Манифест подписывается ed25519, ключ в env `PALMA_SIGNING_KEY`, публичный ключ отдаётся
  на `GET /api/pubkey`. Клиент проверяет подпись перед установкой.
- Файлы без действующей подписки (`free` и образ с `pro: true`) не отдаются: `402`
  с телом `{"error": "subscription_required"}`. Метаданные отдаются всегда.
- Загрузка бэкапа домашней папки — функция Pro и Lifetime: `free` → `402 subscription_required`.
  Скачивание своего бэкапа разрешено и после окончания подписки: файлы не теряются, окружение
  продолжает работать, заканчиваются только обновления и новые загрузки.
- Все ответы — JSON с `Content-Type: application/json; charset=utf-8`, ошибки в формате
  `{"error": "snake_case_код"}`, никаких HTML-страниц с трейсбеками.
- Логи: одна строка на запрос, без тела и без токенов.

## Админский экран

Один статичный HTML-файл `backend/admin/index.html`, который сервер отдаёт на `GET /admin`.
Собирается строго по `design/DESIGN.md`: токены оттуда, светлая тема, один акцент,
без рамок и градиентов, шрифт Inter. Формы — не браузерные дефолты: свои поля, свои состояния
фокуса и ошибки, кнопка высотой 56, зоны нажатия не меньше 48.
Сверить глазами с `design/shots/06-podpiska.png` — плотность, поля, цвет текста, тень.

## Тесты

`backend/tests/` на pytest. Покрыть: health, манифест и `304`, `Range` и докачку с середины,
`404`/`503` на образ, `402` без подписки, все четыре исхода `sub/verify`, конфликт устройства,
`403` без админского токена и `403` с мусорным токеном (проверять именно код, а не падение),
подпись манифеста проверяется публичным ключом, бэкап домашней папки туда-обратно.
Все тесты зелёные. Запуск: `python -m pytest -q`.
