## Конспект

- Программа: `package main`, `import "fmt"`, `func main()`. `fmt.Println` разделяет аргументы пробелом и ставит перевод строки; `fmt.Printf("%d %s %v\n")`.
- Переменные: `var x int = 5`, короткая форма `x := 5` только внутри функций; нулевые значения: `0`, `""`, `false`, `nil`. Неиспользуемая переменная — ошибка компиляции.
- Функции: несколько возвращаемых значений `func div(a, b int) (int, error)`; именованные результаты.
- Срезы: `[]int{1,2,3}`, `s[i:j]` берёт элементы с i по j-1; `len`, `cap`; `append` может выделить новый массив; срез, взятый из массива, разделяет с ним память.
- Карты: `map[string]int`, `make`; запись в nil-карту — паника; `v, ok := m[k]`; `delete`; порядок обхода `range` не определён.
- Структуры и методы: `type User struct{...}`; метод с получателем-значением работает с копией, с получателем-указателем меняет оригинал.
- Интерфейсы реализуются неявно: тип подходит, если у него есть все методы интерфейса.
- Ошибки: интерфейс `error` с методом `Error() string`; `errors.New`, `fmt.Errorf("...: %w", err)`; проверка `if err != nil`.
- `defer` выполняется при выходе из функции, в обратном порядке (стек); `panic` прерывает выполнение, отложенные вызовы при этом выполняются.
- Горутины: `go f()`; `main` не ждёт горутины — нужен `sync.WaitGroup` или канал.
- Каналы: `make(chan int)` — небуферизованный, отправка блокируется до получения; `make(chan int, 2)` — буфер; `close`, `for v := range ch`; `select` ждёт первый готовый канал.
- Модули и пакеты: `go mod init имя`, `go.mod`, `go.sum`; экспортируются имена с заглавной буквы.
- HTTP: `http.HandleFunc("/", h)`, `http.ListenAndServe(":8080", nil)`.

## Почему без компиляции

Компилятора Go в образах нет (это сотни мегабайт на каждую из шести систем). Задачи: «что напечатает», выбор варианта, поиск ошибки. Ответы «что напечатает» сверены вручную по правилам выше; для каждого примера порядок вывода детерминирован (нет обхода карт и гонок горутин без синхронизации).
