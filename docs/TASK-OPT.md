# Задача: оптимизация кадрового конвейера и супервизора Matrux

Проект: `/root/palma` (Android, Kotlin + Compose; гость — Linux в proot; картинка стола идёт по VNC).
Подробный аудит с номерами правок уже лежит в `docs/AUDIT.md` — он и есть основной источник задач.
Прочитай сначала `CLAUDE.md`, затем `docs/AUDIT.md` целиком, затем сами файлы.

## Что сделать

Реализовать правки из `docs/AUDIT.md` в порядке приоритета его финального списка («Десять главных правок»).
Разрешённые файлы:

- `app/src/main/java/ru/palma/app/shell/VncClient.kt`
- `app/src/main/java/ru/palma/app/session/SessionController.kt`
- `app/src/main/java/ru/palma/app/ui/screens/DesktopScreen.kt`
- `app/src/main/java/ru/palma/app/MainActivity.kt`, `AppGraph.kt`
- `image-build/palma-session` (shell-супервизор гостя)

**Не трогать** каталоги `image-build/*rootfs`, `backend/data/images`, `dist/`, `art/`, `stand/` — они заняты
другими исполнителями и большие (гигабайты).

## Обязательные условия

1. **Порядок каналов (правка 1.1) — только с доказательством.** Аудит утверждает, что R и B перепутаны, но
   скриншоты с телефона показывают верные цвета (оранжевые обои остаются оранжевыми). Меняй `SetPixelFormat`
   и строковое копирование (1.2) **только** если приложишь аргумент, который проверяется командой; если
   доказательства нет — оставь как есть и напиши в отчёте «1.1 отклонена, причина».
2. **Ни одного комментария в коде.** Ни пояснительных, ни TODO. Это правило заказчика.
3. **Размеры — в десятичных МБ** (`/1e6`), не MiB.
4. Сборка обязана быть зелёной: `ANDROID_HOME=/opt/android-sdk ./gradlew assembleDebug` → `BUILD SUCCESSFUL`.
   В конце версию подними: `palma.versionName`/`palma.versionCode` в `gradle.properties`.
5. Правки, для которых нужен телефон (замеры FPS, проверка `-noshm`, поворот живьём), **не применять молча**:
   либо оставить помеченными в отчёте как «ждёт проверки на телефоне», либо приложить вывод команды с телефона.
6. Приложение для RuStore, требования Google Play не применять. Интерфейс — русский.

## Отчёт

Файл `docs/OPT-REPORT.md`, по-русски, без вводных фраз:

- по каждому пункту аудита: номер, файл:строка, что изменено (или почему отклонено);
- какие проверки прогнаны и с каким выводом (сборка, `grep` на отсутствие комментариев, прогон тестов);
- отдельный список «ждёт проверки на телефоне» с командой, которой это проверить;
- что осталось незакрытым.

В конце выведи команды, которыми проверяется результат, чтобы их можно было повторить.
