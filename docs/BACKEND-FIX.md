# Бэкенд Palma — правки после ревью

Три решения заказчика. Первые два обязательны, третье подтверждено.

## 1. Доступ к чужому бэкапу

Сейчас `GET /api/home/{device_id}` отдаёт архив любому, кто знает `device_id`. Так нельзя.

Сделать привязку устройства к секрету:

- `POST /api/devices/register` → тело `{"device_id": "<client-generated>", "name": str|null}`
  → ответ `{"device_id", "device_key", "tier", "expires_at"}`. `device_key` — 32 случайных байта
  в base64url, хранится у сервера хешем (sha256), показывается ровно один раз.
- Повторная регистрация того же `device_id` без верного ключа → `409 device_exists`.
- Все маршруты, привязанные к устройству, требуют заголовок `X-Device-Key` и сверяют его
  с сохранённым хешем: `POST/GET /api/home/{device_id}`, `GET /api/sub/status`,
  `POST /api/sub/verify`. Неверный или отсутствующий ключ → `403` (не `500`).
- Чужое устройство с верным своим ключом → `403`, а не `404`: наличие чужого бэкапа не раскрываем.
- Проверку ключа делать сравнением байтов с защитой от исключений (как с админским токеном).

Тесты: регистрация, повторная регистрация, доступ со своим ключом, отказ с чужим ключом,
отказ без ключа, мусорный ключ (в том числе кириллица и `\xff\xfe\x00\x80`) → `403` без падений.

## 2. Бэкап — функция Pro

Загрузка бэкапа остаётся за Pro и Lifetime, как сделано. Добавить это правило в `docs/BACKEND.md`
в раздел про подписку, чтобы оно не потерялось: `free` → `402 subscription_required`.
Скачивание своего бэкапа при истёкшей подписке разрешить: человек не должен терять свои файлы,
окружение продолжает работать, заканчиваются только обновления и новые загрузки.

## 3. Значения в DESIGN.md

## Проверить и отчитаться

Показать командами: `pytest`, `ruff check`, живой прогон — регистрация устройства, скачивание
своим ключом (`200`) и чужим (`403`), `Range`-докачка бэкапа, отсутствие токенов и ключей в логах.
