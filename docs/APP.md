# Приложение Palma — задание на сборку

Модуль: `app`. Пакет `ru.palma.app`. Kotlin + Jetpack Compose. minSdk 26, targetSdk 34 (платформа 34 уже стоит локально).
Эталон вида — `design/mockup.html` и `design/shots/*.png`. Значения — только из `design/DESIGN.md`.

## Экраны (один в один с макетами)

1. **Главная** — что установлено сейчас, одно главное действие («Запустить» или «Установить Debian 12»),
   состояние подписки одной строкой, размер образа. Ничего больше на первом экране.
2. **Каталог** — три дистрибутива. У каждого: настоящее имя и логотип, размер, время установки,
   что внутри (рабочий стол, набор программ), метка Pro у платных.
3. **Установка** — один реальный прогресс: скачано и распаковано, без фейковых этапов
   и без бесконечного спиннера. Отмена по кнопке, докачка после обрыва.
4. **Переход в систему** — полноэкранный запуск с реальными шагами (проверка подписки, распаковка,
   подъём proot, старт X11). Ошибка на любом шаге — словом и с кнопкой «Повторить».
5. **Десктоп** — живое окно системы, панель управления сверху, кнопка «Стоп», возврат в приложение.
6. **Подписка** — Free / Pro (месяц, год) / Lifetime, бесплатный триал, что даёт каждый,
   где требуется VK ID, кнопка отписки. Недельной подписки нет — заказчик её не подтверждал.

## Тема

`ui/theme/` — единственное место с цветом, шрифтом, радиусом, тенью. Состав ровно как в DESIGN.md,
имена токенов те же (`canvas`, `surface`, `ink`, `muted`, `accent`, `hairline`, `radiusCard`).
Compose `MaterialTheme` заполняется из этих значений; ни один экран не задаёт цвет сам.
Шрифт Inter — файлом в `res/font`, не из сети.

## Состояния (обязательно на каждом экране)

Пусто (что сделать), загрузка (реальный прогресс, не спиннер), ошибка (что случилось и что нажать),
нет сети, нет подписки (402 от сервера), доступ отозван. Ни один экран не показывает пустоту молча.

## Сервер

Клиент — OkHttp, один слой `data`. Адреса и токены — из `BuildConfig`, не в коде.
Манифест проверяется подписью ed25519 по публичному ключу с `GET /api/pubkey`; подпись не сходится —
загрузка не начинается, экран говорит причину. Образ качается с `Range` и докачкой, sha256
сверяется после распаковки. Коды: 402 → «нужна подписка», 403 → «нет доступа», 503 → «образ
недоступен», 0/таймаут → «нет связи».

Устройство регистрируется один раз: `POST /api/devices/register` с `device_id`, в ответ приходит
`device_key` — хранить его в приватном хранилище приложения и присылать заголовком `X-Device-Key`
в `sub/status`, `sub/verify`, `home` и при скачивании Pro-образов. Без ключа эти запросы отвечают `403`.
Ключ не логировать, не отправлять в аналитику, не хранить в открытом виде на диске.

## Оболочка

Движок proot и распаковка tar.zst — отдельными функциями, без них приложение должно собираться
и показывать каталог. X11-канал обязателен, VNC — запасной режим. Фоновая работа — foreground
service с уведомлением; выгрузка из памяти не должна убивать установку.

## Правила проекта

- Ни одного комментария в коде.
- Ни одного своего цвета, шрифта, радиуса, длительности вне `ui/theme`.
- Никаких эмодзи в интерфейсе, никаких заглушечных картинок: логотипы дистрибутивов — настоящие файлы.
- Тексты короткие, без восклицаний и без «Давайте».

## Что сдать

- Собранные APK: `dist/SIRENA-подобное` имя не нужно — `palma-<версия>.apk` и `palma-<версия>-pro.apk`
  (Pro-сборка — только если заказчик попросит).
- Проверка по файлу: `aapt2 dump badging` — пакет, код, версия, метка.
- Тесты на логику: разбор манифеста, проверка подписи, докачка, разбор кодов ошибок, состояние экранов.
- Стенд для съёмки: шесть экранов открываются в браузере на телефонной ширине 390×844
  (как в `design/mockup.html`), чтобы сверять с макетами глазами.
- Отчёт: что сделано, что проверено командой и с каким выводом, что осталось.
